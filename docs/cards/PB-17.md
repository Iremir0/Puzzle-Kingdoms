# PB-17 Release build

Owner: — · Milestone: M6 · Size: S · Branch: `feature/PB-17-release-build` · Replaces: M6-05 ·
Needs: PB-1

## Why
Google Play only takes a signed Android App Bundle (AAB). The signing key is
the identity of the app forever: lose it and you cannot update the game. This
card makes the first store-ready build and sets up the key safely.

## Today
- Package name `com.puzzlekingdoms.game`, portrait, IL2CPP, ARM64, min API 26
  (from `ProjectSetup`).
- Dev APK command exists ([AndroidBuild.cs](../../Assets/_Project/Scripts/Editor/AndroidBuild.cs)).
- No icon, default Unity splash, no release key.

## Build
1. **Icon:** 512×512 master + adaptive icon (foreground + background layers,
   432×432 with the important part inside the centre 66%). Simple: a gold crown
   over a red gem on navy. Set in *Player Settings → Icon*.
2. **Splash:** navy background, logo; Unity 6 lets you hide the Unity logo on
   paid plans only; otherwise keep it, add our logo after it.
3. **Release keystore:** create in *Player Settings → Publishing Settings →
   Keystore Manager*. Store the `.keystore` file and passwords **outside the
   repo** (password manager + a second backup both of you can reach).
   `.gitignore` already ignores `*.keystore`, `*.jks` and `/Builds/`; keep it so. Plan to use Google Play App
   Signing (upload key) so a lost upload key can be reset.
4. **Release build command:** `AndroidBuild.BuildReleaseAab` (no development
   flag, `buildAppBundle = true`, reads keystore path and passwords from
   environment variables, never from files in the repo). Output
   `Builds/Android/PuzzleKingdoms.aab` (gitignored).
5. **Version:** `bundleVersion` 0.1.0, `bundleVersionCode` 1; write in
   CONVENTIONS.md how to bump them.
6. Install the AAB on a phone via Play Console internal testing (or
   `bundletool`) and play 1-1.
